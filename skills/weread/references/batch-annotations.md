# 批量私密批注：执行手册

适用于整章笔记、多条材料同步、补全既有批注，以及中断后继续。
按下面顺序执行；当前步骤的完成条件未满足时，保存进度并处理缺口。
账号、认证和限速规则以主 SKILL.md 为准。本手册不提供批量 CLI 命令；
使用已安装 CLI 的单条命令完成操作，自动化时用参数数组调用进程。

## 1. 固定来源与任务边界

读取当前绑定的完整源文档，保存文档 ID、版本、原始快照和 SHA-256。
“全部笔记”按实际学习项枚举，不按其他应用的勾选框过滤。操作控件不作为笔记内容。
给每项保存稳定 `itemId`（来源块 ID 或已有元素 ID），而非仅用标题或数组序号。

先生成每项的最终完整正文，再写入。保留标题、释义、表格、原文解读、例句、
练习、答案、版本、出处及链接。提取富文本时同时提取链接目标：XML 的 `itertext()`
或 HTML 的纯文本提取会丢掉 `href`。可在正文末尾列出对应的链接标题和 URL。
仅在用户明确要求摘要时压缩内容。

完成条件：来源项数等于计划项数，itemId 无重复，每项非空，源链接逐项对应到正文。
抽查复杂表格、练习及带链接项的序列化结果；结构检查需覆盖所有项。

## 2. 固定电子书位置

从书架或书籍结果确认 bookId，从 `book chapters` 获取 chapterUid；书面章号不能代替 UID。
对原文调用 `book search BOOK_ID "原文" --chapter-uid UID --json`，按主技能的定位检查选定候选。
保存返回的 range、markText、context、source，以及返回时存在的 chapterSha256。
同一次计划内，相同查询可以复用已保存响应。

| 遇到的情况 | 必须采取的动作 |
| --- | --- |
| 多处相同词语 | 用来源句子、段落、版本和对照组唯一确定候选；仍不唯一则标记 unresolved |
| 中英对照或重复翻译 | 确认是材料引用的语言、版本、段落，不能仅匹配字符串 |
| 英美修订文字相邻 | 选实际存在的版本文字或较短的唯一锚点；保存选取理由，不拼接不存在的连续句子 |
| 匹配为空或 complete 不为 true | 保留缺口并排查，当前项不能写入 |
| range 长度不同于引用文本长度 | 保留原 range；标签、实体会导致差异 |
| 只有本地原始 EPUB | 用它找原文，再由 book search 取得微信读书范围 |

仅在已有**服务端转换后章节 HTML**且能验证其 SHA-256 与新鲜搜索返回的章节指纹一致时，
才可复用经验证的离线定位实现。当前没有通用的章节导出命令；缺少这些条件就使用 book search。
书籍、版本、指纹变化后重新定位，不复用旧坐标。

完成条件：每个待写项都有唯一且有证据的锚点；未解决项单列，不能算作成功或静默丢弃。

## 3. 保存计划并查重

在私有工作目录保存 plan.json、state.json 和 receipts/。正文、章节及账号资料不提交到公共仓库。
计划至少保存以下字段；示例中的 ID 和位置只是结构占位，不能直接调用：

```json
{
  "account": "selected-account",
  "source": {"id": "document-id", "revision": "revision", "sha256": "snapshot-sha256"},
  "bookId": "book-id",
  "chapterUid": 15,
  "items": [{
    "itemId": "source-block-id",
    "content": "完整正文及链接",
    "contentSha256": "utf8-content-sha256",
    "range": "100-110",
    "markText": "原文",
    "context": "已确认的上下文",
    "locator": {"source": "reader-html", "chapterSha256": "chapter-sha256"},
    "reviewId": null,
    "expectedPreviousContentSha256": null
  }]
}
```

保存整个计划的哈希。恢复时核对账号、来源、书籍、章节和计划哈希；更改计划意味着重新核对受影响项。
用 `notes bookmarks BOOK_ID --json` 查划线；按书籍、章节、range、markText 复用匹配划线。
批注按稳定 itemId 对应的 reviewId 查重。相同位置的不同学习项可以共享一条划线，分别保留批注。
不能仅凭相同 range 合并笔记，也不能把“划线存在”当作“批注存在”。

优先使用此前的回执或任务状态找 reviewId，然后 `review single` 核实。
若笔记列表接口失败，保留错误；有确定 ID 的任务可以继续逐条读取。
缺少回执且无法排除先前已写入时，将相关项标记为待核对，不能推断列表失败意味着没有笔记。

完成条件：每项明确为新增、复用、编辑或待核对；编辑项保存先前完整正文及其哈希。

## 4. 串行写入与回读

同账号只运行一个队列，读取、搜索、写入、验证均走主技能的限速规则。
先运行计划中的第一项并完成回读，再继续其余项；首项成功也计入进度，不能再次创建。
自动化程序需持有进程锁，并在退出、异常、取消时保存状态。

每项严格执行：

1. 没有匹配划线时，保存写入意图后执行 `notes add-bookmark`。保存响应及 bookmarkId，
   读取划线列表确认书籍、章节、range、markText。已有划线直接复用。
2. 有 reviewId 时，先 `review single`：内容与目标完全相同且私密则复用；需要编辑时，
   将当前完整正文哈希与计划的旧正文哈希比较。不同则标记 conflict，防止覆盖用户修改。
3. 保存批注写入意图（itemId、动作、计划哈希、目标正文哈希、已有 ID），再调用：
   - 新增：`review add BOOK_ID CONTENT --type 1 --chapter-uid UID --range RANGE --abstract MARK_TEXT --private --json`
   - 编辑：`review edit REVIEW_ID CONTENT --private --json`
   每条命令都带已选定的 `--account`。CONTENT 是计划的完整正文；编辑是整段替换，不是追加。
4. 收到响应立即落盘，再更新状态中的 ID。状态使用临时文件加原子替换保存。
5. 用 `review single REVIEW_ID --json` 回读，逐项比较 `review.bookId`、`chapterUid`、`range`、
   `abstract`、完整 `content` 和 `isPrivate === 1`。全部满足才标记 verified。

调用进程时使用参数数组（如 Python subprocess.run([...])），正文不拼接进 shell 命令。
写入失败、返回内容非 JSON、缺 ID、验证不符，均保存证据并停止写队列；按下节处理。

## 5. 故障与恢复

| 保存的状态或错误 | 恢复动作 |
| --- | --- |
| verified 且计划未改变 | 保留该 ID 和已验收回执，继续下一项；最终报告说明回读时间 |
| 成功响应已保存但 state 尚未更新 | 从响应恢复 ID，执行回读；不重发创建 |
| 已有 ID，但回读失败 | 只重试读取；未验证前不能重复创建 |
| 只有写入意图，没有确定响应（包括超时） | 标记 outcome_unknown；先查服务端或可靠回执。不能删除意图后盲重发 |
| 划线成功而批注未开始 | 复用该划线，只执行后续批注步骤 |
| HTTP 429 或明确“操作频繁” | 立即停止写队列，遵守 Retry-After；没有提示则至少等 60 秒，再做一次只读检查。仍失败则保留进度并报告；恢复时将间隔加倍 |
| 参数错误（例如某列表返回 -2003） | 保存命令、接口、错误码及消息，排查参数；不重新登录、不循环换 count |
| 认证、权限、章节校验错误 | 按主技能诊断；修复前保持暂停，不能切换账号或接口绕过 |
| 源文档变化、编辑冲突或私密校验不符 | 保存差异，重新核对受影响计划；不能将它计为完成 |

错误码必须结合具体接口和消息解释。某个接口的 -2010/-2013 不能直接套用到所有接口。
任何重试前先判断上次操作是否可能已生效；写入结果不明确时，重试额度永远不是再次创建的许可。

## 6. 最终验收

用本地脚本逐条比较计划和已保存的服务端回读，检查完整正文及链接、位置、私密状态，
确认不同 itemId 没有意外共享 reviewId。重新读取划线列表核对所有目标锚点。
重新读取来源，比较版本和内容哈希；来源变化就报告计划所对应的旧版本并核对差异。

满足以下条件才报告“全部完成”：

- 计划的每项都有唯一 reviewId、匹配的完整正文和位置、isPrivate 为 1 的回读证据。
- verified 数等于计划项数；unresolved、conflict、outcome_unknown、failed 均为 0。
- 所有原文锚点有对应划线；源内容及链接无遗漏。

最终报告计划总数、新增/编辑/复用数、私密核验数、未解决数和实际限速设置，附本地验收文件。
多条笔记共享划线时分别报告笔记数和不同范围数，两者无需相等。后台进程仍在运行时仅报告进度。
